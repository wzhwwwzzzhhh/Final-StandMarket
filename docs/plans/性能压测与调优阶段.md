# 性能压测与调优阶段

## 业务目标

落地商品、订单和秒杀核心链路的数据库索引，并对秒杀提交入口实施本地 Sentinel QPS 限流，避免突发流量耗尽应用、Redis 或消息队列连接资源。

## 执行步骤

1. 基于 `项目优化执行方案.md` 和现有建表、Mapper 查询确认索引名称和列顺序。
2. 在 `mysql/add_indexes.sql` 提供幂等索引迁移，运行前由 `information_schema.statistics` 检查索引是否存在。
3. 在 `fashion-server` 增加 Sentinel 依赖、AOP 支持和启动时 QPS 规则；对 `SeckillCouponServiceImpl.seckillCoupon` 增加限流与异常降级处理。
4. 新增商品查询、秒杀抢购、80/20 混合场景 JMeter 脚本，脚本参数支持命令行覆盖目标地址、令牌和秒杀券 ID。
5. 在具备 MySQL、Redis、RabbitMQ、应用和 JMeter 的独立压测环境执行脚本；将 JTL/HTML 报告中的结果填入压测报告，并用数据库 SQL 核验超卖数量。

## 验收标准

- 索引脚本可重复执行且仅创建缺失索引。
- `seckillCoupon` 资源按 500 QPS 快速失败，限流和异常均返回统一业务错误结果。
- 三个 JMeter 脚本可在非 GUI 模式运行并输出 JTL 与 HTML 报告。
- 若本地缺少完整依赖环境，报告必须使用“待环境执行”，不填造测试指标。

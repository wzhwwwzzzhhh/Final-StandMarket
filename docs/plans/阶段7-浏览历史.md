## Context

Phase 7 目标：实现用户浏览历史，低成本个性化。核心用 Redis List 记录浏览商品（新浏览放头部、去重、截断 50 条），个人中心展示最近浏览。

### 方案

| 环节 | 方案 |
|------|------|
| 存储 | Redis List，key `user:browse:{userId}`，值为 productId 字符串 |
| 记录 | `LREM` 去重 → `LPUSH` 头部插入 → `LTRIM 0 49` 截断 50 条 |
| 查询 | `LRANGE 0 -1` 取 id 序列（时间倒序），批量查商品关联信息并保持顺序 |
| 清空 | `DEL` 删除 key |
| 鉴权 | `/user/browse/**` 已被 LoginInterceptor 保护，BaseContext 取 userId |

## 接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/user/browse/{productId}` | 记录浏览（需登录） |

> 审查子代理完成后在此记录

### 2026-08-07 code-reviewer 审查

**结论**：通过（审查提出的 4 项问题已全部修复）

**审查发现并已修复的问题：**

1. 【一般】去重/置顶/截断非原子，并发下会产生重复浏览记录 — 已改为 Lua 脚本 `resources/lua/browse_record.lua` 一次原子执行（`LREM 0 → LPUSH → LTRIM 0 49 → EXPIRE`）
2. 【一般】浏览历史 Redis key 无过期时间 — 已加 TTL（30 天，每次记录续期）
3. 【一般】`selectBatchByIds` 未过滤 `status = 1`，下架商品仍出现在历史 — 已与 `getById` 对齐，批量查询增加 `status = 1` 过滤
4. 【一般】`recordBrowse` 可能因 token 过期 401 触发全局强制跳转登录，把浏览商品页的用户踢出 — 已给 `request.js` 增加 `skipAuthRedirect` 配置项（默认不变），`browse.js` 记录接口开启后 401 静默忽略

**保留项（防御性冗余，未处理）：**

- 控制器内 `userId==null` / `productId==null` 防御性检查（LoginInterceptor 已保证登录、路径变量已保证非空）

**亮点**：Lua 原子操作符合项目秒杀链路先例；查询层对脏数据防御到位并保持 Redis 时间倒序；鉴权链路完整（JwtUserInterceptor 写上下文 → LoginInterceptor 拦截 → afterCompletion 清理防串用）；SQL 全参数化；前端空态/加载态/清空二次确认/键盘可访问性齐全。

# JMeter 压测方案

> 目标接口：秒杀抢购、商品查询
> 工具：Apache JMeter 5.x（Windows）

---

## 一、待压测的接口

| 场景 | 接口 | 方法 | 说明 |
|:----:|------|:----:|------|
| **场景A** | `GET /api/user/product/page?page=1&pageSize=10` | 读 | 商品列表查询 |
| **场景B** | `GET /api/user/seckill/coupon/list` | 读 | 秒杀券列表 |
| **场景C** | `POST /api/user/seckill/coupon/{couponId}/orders` | 写 | **秒杀抢购（核心）** |

> 注意：场景B和场景C需要 JWT Token，请求头加 `Authorization: Bearer {token}`

## 三、配置步骤（手把手）

### 🔧 准备工作：获取 Token

因为秒杀接口需要登录，JMeter 有两种方式处理：

**方式A（推荐）：先手动登录，把 Token 贴到 JMeter 里**

> 通过任意方式登录，从响应中拿到 JWT Token，比如：
> `Bearer eyJhbGciOiJIUzI1NiJ9...`

**方式B：JMeter 先发登录请求，提取 Token 再复用**

> 配置一个 HTTP 请求先登录 `/api/user/login`，然后用 JSON 提取器取出 Token，设置到后续请求的 Header 中。

---

### 📝 场景A：商品列表查询（读压测）

**步骤：**

1. 右键「测试计划」→ 添加 → Threads → **线程组**
   - 线程数：`100`
   - Ramp-Up 时间：`5` 秒
   - 循环次数：`100`

2. 右键线程组 → 添加 → Sampler → **HTTP 请求**
   - 协议：`http`
   - 服务器：`localhost`
   - 端口：`8080`
   - 路径：`/api/user/product/page`
   - 参数：
     - `page` = `1`
     - `pageSize` = `10`

3. 右键线程组 → 添加 → 监听器 → **查看结果树**（调试用）
4. 右键线程组 → 添加 → 监听器 → **聚合报告**（看最终数据）

---

### 📝 场景C：秒杀抢购（写压测，核心）

**这套配置是重中之重：**

#### 步骤1：准备工作
1. 确保有一个**有库存**的秒杀券（比如 ID=1，库存=5000）
2. 准备一个 Redis 预热的秒杀券：先调一下秒杀券列表接口确认
3. 拿到一个有效的 JWT Token

#### 步骤2：配置线程组
- 线程数：`200`
- Ramp-Up 时间：`10` 秒（模拟用户逐渐涌入）
- 循环次数：`50`
- 总计请求数：`200 × 50 = 10000`

#### 步骤3：配置 HTTP 请求默认值
右键测试计划 → 添加 → 配置元件 → **HTTP 请求默认值**
- 协议：`http`
- 服务器：`localhost`
- 端口：`8080`

#### 步骤4：配置 HTTP 信息头管理器
右键线程组 → 添加 → 配置元件 → **HTTP 信息头管理器**
- 添加一行：
  - 名称：`Authorization`
  - 值：`Bearer 你登录拿到的JWTToken`

#### 步骤5：配置 HTTP 请求（秒杀）
右键线程组 → 添加 → Sampler → **HTTP 请求**
- 名称：`秒杀抢购`
- 路径：`/api/user/seckill/coupon/1/orders`
- 方法：`POST`
- 注意：`1` 是秒杀券 ID，换成您实际配置的

#### 步骤6：添加监听器
右键线程组 → 添加 → 监听器 → **聚合报告**
右键线程组 → 添加 → 监听器 → **图形结果**
右键线程组 → 添加 → 监听器 → **用表格查看结果**

---

### 📝 场景B+C：混合场景（最接近真实）

**线程组配置：**
- 线程数：`200`
- Ramp-Up：`10` 秒
- 持续时间：`300`（5分钟）

**添加逻辑控制器 → 随机控制器：**
- 80% 概率：商品列表查询（GET）
- 20% 概率：秒杀抢购（POST）

## 四、重点关注的数据

压测完后，打开 **聚合报告**，看这几列：

| 指标 | 列名 | 说明 |
|:----:|------|------|
| **吞吐量** | `Throughput` | 每秒处理请求数（QPS） |
| **平均响应** | `Average` | 平均耗时（ms） |
| **P90/P99** | `90% Line` / `99% Line` | 90%/99% 的请求在这个时间内完成 |
| **错误率** | `Error %` | 失败的请求占比 |
| **中位数** | `Median` | 一半请求的响应时间 |

### 预期参考值（优化后）

| 场景 | QPS 预期 | 平均 RT | P99 |
|:----:|:--------:|:-------:|:---:|
| 商品列表查询 | 2000+ | < 50ms | < 100ms |
| 秒杀抢购 | 800+ | < 100ms | < 200ms |
| 混合场景 | 1500+ | < 80ms | < 150ms |

## 六、常见问题

### Q：压测秒杀时提示未登录？
A：检查 HTTP 信息头管理器是否配了 `Authorization`，并且 Token 是否有效

### Q：秒杀券库存不够？
A：在管理端添加一个秒杀券，库存设大一点（如 5000），并预热到 Redis

### Q：压测数据不准？
A：跑之前先**单独跑一次**让 JVM 预热，正式测试时忽略前 100 个请求的数据

### Q：JMeter 报错 `Connection refused`？
A：确认后端服务已启动，前端是否用 `/api` 代理到 8080 端口。可以直接测后端：使用 `localhost:8080` 并去掉路径中的 `/api`

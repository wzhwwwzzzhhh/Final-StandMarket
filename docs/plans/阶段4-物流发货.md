# Phase 4: 物流/发货

> 基于主计划 [功能拓展主计划.md](功能拓展主计划.md) Phase 4
> 日期: 2026-07-19

## Context

Phase 3 已完成支付宝沙箱支付接入，订单支付成功后状态变为 status=2（待发货）。当前管理端「订单管理」中，待发货订单的"处理"按钮直接调用 `orderService.update()` 将 status 变为 3，没有填写快递信息。用户端已发货订单(status=3)也没有物流信息展示。

Phase 4 的目标是补全发货流程：管理端发货时填写快递公司+快递单号，用户端可查看物流信息。

### 当前订单状态机

```
1(待付款) → 支付 → 2(待发货) → 发货 → 3(已发货) → 确认收货 → 4(已完成)
                                                     取消 → 5(已取消)
```

### 现有相关代码

| 组件 | 状态 | 说明 |
|------|------|------|
| `Orders.java` 实体 | ✅ 有 `deliveryTime`、`estimatedDeliveryTime` | ❌ 缺 `trackingCompany`、`trackingNumber` |
| `OrderMapper.xml` update | ✅ 有 `delivery_time` 等字段 | ❌ 缺 `tracking_company`、`tracking_number` |
| `OrderMapper.xml` insert | ✅ 有 `delivery_time` 等字段 | ❌ 缺 `tracking_company`、`tracking_number` |
| `OrderService.deliver()` | ❌ 不存在 | 需新增 |
| `Admin/OrderController` | ✅ 有 GET/PUT 基础接口 | ❌ 缺专门发货接口 |
| `Admin OrderList.vue` | ✅ 有订单管理列表+详情弹窗 | 处理按钮直接改状态，无发货表单 |
| `Client Order.vue` | ✅ 有订单列表+详情弹窗 | ❌ 缺物流信息展示 |

## 步骤

### Step 1: 数据库 — 添加快递字段

执行 SQL 给 `orders` 表增加快递相关字段：

```sql
ALTER TABLE `orders`
  ADD COLUMN `tracking_company` varchar(50) DEFAULT NULL COMMENT '快递公司',
  ADD COLUMN `tracking_number` varchar(100) DEFAULT NULL COMMENT '快递单号';
```

说明：
- `tracking_company` — 快递公司名称（如：顺丰速运、中通快递、圆通速递）
- `tracking_number` — 快递单号

### Step 2: 后端 — Orders 实体加字段

**修改文件**：`backend/fashion-pojo/src/main/java/com/fashion/entity/Orders.java`

新增字段：

```java
/**
 * 快递公司
 */
private String trackingCompany;

/**
 * 快递单号
 */
private String trackingNumber;
```

### Step 3: 后端 — OrderMapper.xml 支持新字段

**修改文件**：`backend/fashion-server/src/main/resources/mapper/OrderMapper.xml`

- `update` SQL 中增加 `tracking_company` 和 `tracking_number` 的 `<if>` 条件
- `insert` SQL 中增加 `tracking_company` 和 `tracking_number` 字段（插入时可为 NULL，不影响现有逻辑）
- `select` 查询中无需改（`select *` 自动带出新字段）
- `listUserOrders` / `listOrders` / `getById` 等 `select *` 查询无需改动

### Step 4: 后端 — OrderService 添加发货方法

**修改文件**：
- `backend/fashion-server/src/main/java/com/fashion/service/OrderService.java`
- `backend/fashion-server/src/main/java/com/fashion/service/impl/OrderServiceImpl.java`

新增接口方法：

```java
/**
 * 发货
 * @param id 订单ID
 * @param trackingCompany 快递公司
 * @param trackingNumber 快递单号
 */
void deliver(Long id, String trackingCompany, String trackingNumber);
```

实现逻辑（`@Transactional`）：
1. 查询订单，校验存在性
2. 校验 status 必须为 2（待发货）
3. 设置 `trackingCompany`、`trackingNumber`
4. 设置 `deliveryTime = LocalDateTime.now()`
5. 设置 `status = 3`（已发货）
6. 调用 `orderMapper.update(order)`

### Step 5: 后端 — Admin OrderController 增加发货接口

**修改文件**：`backend/fashion-server/src/main/java/com/fashion/controller/admin/OrderController.java`

新增接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `PUT` | `/admin/order/deliver` | 发货（快递公司+单号） |

请求体：

```json
{
  "id": 订单ID,
  "trackingCompany": "顺丰速运",
  "trackingNumber": "SF1234567890"
}
```

### Step 6: 后端 — UserOrderController 增加物流查询接口

**修改文件**：`backend/fashion-server/src/main/java/com/fashion/controller/user/UserOrderController.java`

新增接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/user/order/tracking/{orderId}` | 查询物流信息 |

返回：

```json
{
  "code": 1,
  "data": {
    "trackingCompany": "顺丰速运",
    "trackingNumber": "SF1234567890",
    "deliveryTime": "2026-07-19T14:30:00",
    "status": 3
  }
}
```

若订单未发货（tracking_number 为空）则返回错误提示"暂无物流信息"。

### Step 7: 前端（管理端）— OrderList.vue 发货表单

**修改文件**：`frontend/fashion-admin/src/views/OrderList.vue`

改动内容：

1. **修改「处理」按钮逻辑**：
   - status=2（待发货）时，按钮文案保持"发货"，点击弹出**发货表单对话框**而不是直接改状态
   - 发货表单包含：快递公司（select 下拉选择）+ 快递单号（input）
   - 快递公司选项：顺丰速运、中通快递、圆通速递、韵达快递、京东物流、EMS
   - 表单验证：快递公司必选，快递单号必填（6-30位字母数字）
   - 提交后调用 `PUT /admin/order/deliver`

2. **订单详情弹窗增加物流信息展示**：
   - 已发货(status=3)及以后状态的订单，显示快递公司+快递单号+发货时间
   - 未发货不展示

### Step 8: 前端（用户端）— Order.vue 物流信息展示

**修改文件**：`frontend/fashion-client/src/views/Order.vue`

改动内容：

1. **订单列表项**中，status=3（已发货）时显示物流标签：
   - 在订单头部或底部显示快递公司+单号
   - 文案格式：`📦 顺丰速运：SF1234567890`

2. **订单详情弹窗**增加物流信息区域：
   - 已发货(status>=3)时显示快递公司、快递单号、发货时间
   - 增加在「收货信息」区域下方

### Step 9: 前端（用户端）— 添加追踪 API

**修改文件**：`frontend/fashion-client/src/api/product.js`（或新建 `tracking.js`）

在现有 `orderApi` 中新增方法：

```javascript
// 查询物流信息
getTracking: (orderId) => request.get(`/user/order/tracking/${orderId}`)
```

## 代码审查报告

> 审查日期: 2026-07-19
> 审查人: pr-review-toolkit:code-reviewer
> 审查范围: 10 个文件（后端 6 + 前端 3 + SQL 1）

### 发现的问题及修复

| # | 严重度 | 问题 | 修复方式 |
|---|--------|------|---------|
| 1 | 🔴 Critical | `OrderController.deliver()` 中 `params.get("id").toString()` 在 id 为 null 时触发 NPE，后续的 null check 死代码不生效 | 将 null check 移到 `Long.valueOf()` 之前 |
| 2 | 🟡 Important | `UserOrderController.tracking()` 未校验订单归属，任意用户可查询任意订单的物流信息 | 添加 `BaseContext.getUserId()` 所有权校验 |
| 3 | 🔵 Low | 客户端 `getTracking()` API 方法已定义但未被 Order.vue 调用（物流数据已通过订单详情接口获取） | 保留为扩展点 |

### 已确认正常项

- **实体字段命名**：`trackingCompany` / `trackingNumber` 符合驼峰规范，与 `cancelReason` 等一致
- **MyBatis insert/update**：insert 已包含新字段（NULL 兼容），update 使用 `<if>` 动态 SET
- **Select 查询**：`select *` 自动带出新字段，mapUnderscoreToCamelCase 映射正确
- **事务**：`deliver()` 标注 `@Transactional`，状态/物流/时间原子更新
- **状态校验**：`deliver()` 严格校验 status==2，防止重复发货/非法状态发货
- **状态机兼容**：发货 transition 2→3，与现有状态定义一致
- **权限分离**：发货接口在 `/admin/order/deliver`（仅管理员），物流查询在 `/user/order/tracking`（需 JWT 登录）
- **异常处理**：Service 层 `RuntimeException` 被 Controller 捕获为 `Result.error()` 返回

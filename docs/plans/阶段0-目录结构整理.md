## 1. 目标

在开始 Docker 化和 GitHub Actions 前，让仓库的文件职责清晰，避免：

- 部署文件、数据库脚本、学习/规划文档散落在根目录；
- 本地 IDE、Codex 状态和临时构建产物被误提交；
- Elasticsearch 插件压缩包堆在根目录且用途不明确；
- 后续生产配置、部署脚本、备份脚本没有固定位置。

本阶段完成后，项目应具备清楚的“应用代码 / 部署配置 / 数据库脚本 / 文档 / 压测 / 本地私有状态”边界。

## 3. 目标目录结构

```text
Final-StandMarket/
├─ backend/                              # Spring Boot / Maven 后端
├─ frontend/
│  ├─ fashion-admin/                     # 管理端 Vue
│  └─ fashion-client/                    # 用户端 Vue
├─ agent-service/                        # Python AI 客服
├─ docker/                               # 容器、部署与运维配置
│  ├─ README.md                          # Docker/部署目录说明与边界
│  ├─ compose/                           # 后续：生产/测试 compose 文件
│  ├─ nginx/                             # 后续：反向代理、静态站点配置
│  ├─ scripts/                           # 后续：部署、备份、恢复脚本
│  └─ elasticsearch/
│     ├─ Dockerfile
│     ├─ docker-compose.yml
│     └─ plugins/                        # 本地保留的 ES 插件离线包
├─ mysql/                                # 现有 SQL 脚本（暂不改变执行逻辑）
│  └─ README.md                          # 脚本用途、风险和后续迁移规则
├─ docs/
│  ├─ plans/                             # 主计划与阶段执行文档
│  ├─ roadmap/                           # 中长期功能/技术路线图
│  ├─ archive/
│  │  └─ local-notes/                    # 历史、本地来源不明确的记录
│  ├─ spring-ai-guide/
│  ├─ 学习路线图/
│  └─ ...
├─ jmeter/                               # 性能测试素材
├─ README.md                             # 项目总入口
├─ AGENTS.md                             # 项目协作规范
└─ .gitignore                            # 排除本地状态、密钥、构建产物
```

目录中暂时创建的空目录会使用 `.gitkeep` 保留，待后续阶段放入真实部署配置后可移除。

## 5. 风险与保护措施

| 风险 | 本阶段控制措施 |
|---|---|
| 移动文件导致文档链接失效 | 检查仓库内引用；当前已发现“功能拓展主计划”文本引用路线图但不是 Markdown 链接，因此无需改链接 |
| 根目录 ZIP 被误删 | 仅移动并在移动前后比对 SHA-256 |
| 将本地工具状态提交到 Git | `.gitignore` 加入 `.codex/`，已有 `.idea/`、`.claude/` 规则保持不变 |
| 误把生产配置或数据带入仓库 | 不移动 `agent-service/.env`，不创建任何真实生产配置；部署目录说明中明确排除敏感文件和数据卷 |
| 把 SQL 整理误变为数据库迁移 | 本阶段只增加 `mysql/README.md`，不修改任何 `.sql` 文件与后端依赖 |

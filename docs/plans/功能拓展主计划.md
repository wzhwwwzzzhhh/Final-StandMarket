## 工作方式

三层任务结构：

| 层级 | 内容 | 产物 |
|------|------|------|
| **第一层** | 确定做什么业务 | 本文件（主计划） |
| **第二层** | 确定该业务的执行步骤 | 各阶段 MD 文件 |
| **第三层** | 确定每步要改/加哪些代码 | 代码实现 + 审查报告 |

每个阶段完成后：
1. 审查子代理（code-reviewer）审查代码
2. 将审查报告记录在阶段 MD 文件中
3. **前端检查**：做该业务时顺便把相关页面精炼/瘦身

## Phase 3: 支付网关

**目标**: 接入支付宝沙箱支付，替换现有手动确认付款。

### 为什么选支付宝沙箱

| 方案 | 优点 | 缺点 |
|------|------|------|
| **支付宝沙箱** ✅ | 个人可接入、文档完善、有沙箱账号模拟全流程、对接简单 | 仅测试环境可用 |
| 微信支付 | 用户覆盖广 | 需营业执照，个人开发者无法正式接入 |
| Stripe（国际） | 文档好 | 国内用户不便，非目标场景 |

**结论**: 支付宝沙箱最适合个人项目展示，可完整演示"下单→支付→回调"闭环。

### 数据库改动

`orders` 表已有 `pay_method`、`pay_status`、`checkout_time` 字段。

新增 `payment` 表（已有部分代码在 untracked 区可复用）：

```sql
CREATE TABLE `payment` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `order_id` bigint NOT NULL COMMENT '订单id',
  `order_number` varchar(50) NOT NULL COMMENT '订单号',
  `payment_no` varchar(100) DEFAULT NULL COMMENT '支付流水号（第三方返回）',
  `pay_method` tinyint NOT NULL COMMENT '支付方式 1微信 2支付宝',
  `amount` decimal(10,2) NOT NULL COMMENT '支付金额',
```

## Phase 6: Elasticsearch 搜索增强

**目标**: 提升 ES 搜索的准确率和召回率。

### 现状问题

- `multi_match` + `best_fields`，错一个字就搜不到
- 无 IK 分词，中文搜索效果差
- 无错误处理（ES 挂了直接崩）
- 无分类/价格筛选
- 无搜索结果高亮

### 改进方案

| 项 | 当前 | 改进后 |
|----|------|--------|
| 分词 | 无 | 配置 IK 分词器（`ik_max_word` + `ik_smart`） |
| 拼音 | 无 | 拼音分词：搜"ms"能搜到"码衫" |
| 权重 | name^3, description^2, tag | 精细化权重调节 |
| 容错 | fuzziness: AUTO | IK + 拼音双保险 |
| 筛选 | 无 | 支持 categoryId、priceRange、tag |
| 排序 | 仅 _score | 支持销量、价格、综合排序 |
| 高亮 | 无 | 搜索关键词高亮 |

### 后端 / 数据

| 文件 | 操作 |
|------|------|
| ES 索引配置 | 重建索引，配置 IK + 拼音分词器 |
| `agent-service/.../tools/search_product.py` | 修改，增加筛选 + 高亮 + 错误处理 |
| `agent-service/.../tools/recommend.py` | 修改，增加筛选参数 |
| ES 数据同步 | Canal / 定时任务 / 管理端手动触发 |

# 安全加固与功能拓展 主计划

> 基于三份代码审计报告（后端 / 前端 / AI服务与数据层）+ 2026 电商行业趋势
> 目标定位：面试 / 简历亮眼优先，兼顾真实可用
> 创建日期：2026-08-07

---

## 一、总览

本项目已完成功能拓展 Phase 1-8（收藏 / 评价 / 支付 / 物流 / 售后 / ES 搜索 / 视觉优化）。经并行代码审计，发现大量"有实现但不可信"的隐患。本主计划分两条主线：

1. **修复线（先做）**：安全加固 + 秒杀链路 Bug 修复 + 前端可信度打磨 —— 这是地基，也是最好的面试素材。
2. **拓展线（后做）**：AI 导购深化、通用优惠券、性能压测、前端体验打磨 —— 差异化亮点。

> 规则：每个阶段必须新建阶段 MD 文档，明确代码文件与验证方式后，才允许改动代码。前端代码无需独立阶段 MD，在后端阶段 MD 中附带说明涉及的前端文件即可。

---

## 二、修复线

### Phase A：安全加固（面试必问，最高优先级）

**目标**：消除匿名调用、越权、篡改等安全漏洞，形成可讲述的"安全加固"面试素材。

| 子项 | 问题 | 位置 | 修复方向 |
|------|------|------|----------|
| A1 | 管理端 `/admin/**` 接口匿名可访问 | `config/Webconfig.java` | 新增 Admin JWT 拦截器，强制校验管理端 token；或统一鉴权框架 |
| A2 | 用户密码明文存储 | `service/impl/UserServiceImpl.java` | 改 BCrypt 哈希 + 登录校验改密码比对 |
| A3 | 下单金额前端可篡改 | `service/impl/OrderServiceImpl.java` | 服务端根据购物车/商品重新计算金额，忽略前端传值 |
| A4 | 支付回调只验签不比对金额 | `controller/notify/PayNotifyController.java` | 比对 `total_amount` 与订单金额，防重放 |
| A5 | 购物车接口越权（IDOR） | `service/impl/ShoppingCartServiceImpl.java` | 所有按 id 操作校验 userId 归属 |
| A6 | 订单详情接口越权（IDOR） | `controller/user/UserOrderController.java` | `getById` 校验归属 |
| A7 | AI 订单查询工具越权/失效 | `agent-service/app/agent/nodes.py` | 后端提供带鉴权的 agent 专用接口，Python 透传用户 token |
| A8 | 前端管理端无登录体系 | `fashion-admin/src` | 补登录页 + 路由守卫 + axios 统一拦截器（token 注入 + 401 处理） |

**前端涉及**：`fashion-admin/src/api/*.js`（统一请求层）、`fashion-admin/src/router`（守卫）、新增登录页。

### Phase B：秒杀链路 Bug 修复（技术亮点所在）

**目标**：修复秒杀核心链路的正确性问题，保住"Redis+Lua+RabbitMQ+Redisson"技术亮点的可信度。

| 子项 | 问题 | 位置 | 修复方向 |
|------|------|------|----------|
| B1 | 超时取消订单 Redis 库存方向错（应 increment 补回） | `service/impl/SeckillCouponServiceImpl.java` | 改补回库存逻辑 |
| B2 | 已支付订单可能被超时任务误取消（乐观锁失效） | `resources/mapper/SeckillOrderMapper.xml` | SQL 加 `and status=待支付` + 校验影响行数 |
| B3 | 建秒杀券 SQL 列值不匹配（10 列对 7 值） | `resources/mapper/SeckillCouponMapper.xml` | 补齐 insert 列/值 |
| B4 | MQ 消费者吞异常，消息丢失无补偿 | `service/impl/SeckillCouponServiceImpl.java` | 手动 ack + 失败重试/死信 + 校验 reduceStock 返回值 |
| B5 | 普通下单不扣减商品库存 | `service/impl/OrderServiceImpl.java` | 事务内校验并扣减库存 |
| B6 | 订单号高并发碰撞 | `service/impl/OrderServiceImpl.java` | 改雪花/分布式 ID 或加唯一索引 |
| B7 | 秒杀券库存预热/持久化问题 | `SeckillCouponMapper.xml` + 预热逻辑 | 与 B3 一并核实补全 |

### Phase C：前端可信度打磨（演示不翻车）

**目标**：消除"演示时翻车"的前端硬伤，统一请求层与状态管理。

| 子项 | 问题 | 位置 | 修复方向 |
|------|------|------|----------|
| C1 | `buyNow()` 跳转不存在的路由 → 白屏 | `fashion-client/src/views/ProductDetail.vue` | 修正跳转路由 |
| C2 | 秒杀页假功能（抢购只弹窗不调接口） | `fashion-client/src/views/Home.vue` | 接真实秒杀接口 |
| C3 | CreateOrder 假保存地址/假地区下拉 | `fashion-client/src/views/CreateOrder.vue` | 接后端地址接口 |
| C4 | 下单数据存储键不一致（localStorage/sessionStorage） | `Order.vue` / `ShoppingCart.vue` / `CreateOrder.vue` | 统一存储或引 Pinia |
| C5 | 订单状态跳转失效（route.query 不读） | `fashion-client/src/views/Profile.vue` / `Order.vue` | 补读 query |
| C6 | 39 处 console.log 残留 + 打印 token | 两端 `api/*.js` | 清理 + 拦截器不打印 token |
| C7 | 硬编码外链图床 15 处 | 两端 views | 收敛到本地/OSS |
| C8 | 无统一请求层（两端各写 axios 实例） | 两端 `api/*.js` | 统一 request.js + 拦截器 |
| C9 | 商品列表加购提示变量名拼错 → `undefined` | `fashion-client/src/views/ProductList.vue` | 修正 |

## 三、拓展线

### Phase D：AI 导购深化（差异化亮点，最贴合 2026 趋势）

**背景**：行业 2026 主旋律是"AI 深度渗透购物环节"（ASOS AI Stylist、Zalando Style Agents）。当前 agent-service 能力边界窄：意图识别 + ES 商品检索 + 失效订单查询 + 假搭配。

**拓展方向**：

| 子项 | 内容 | 技术要点 |
|------|------|----------|
| D1 | 订单/物流/售后查询工具（真实可用） | 后端带鉴权 agent 接口 + Python 透传 token |
| D2 | 尺码推荐 | 身高体重 → 尺码映射规则引擎，接入 `product_sku` |
| D3 | 真实搭配推荐 | 按 category/标签组合，启用 OUTFIT_RULES |
| D4 | 多轮上下文 + 槽位管理 | 修复历史倒序问题，真实 messages 数组传 LLM |
| D5 | LLM 降级兜底 | 超时/异常时规则匹配 + 友好话术，/chat 永不 500 |
| D6 | 会话 TTL + 埋点 | Redis key 设过期；记录 query/intent/点击，反哺排序 |

**前端涉及**：`fashion-client/src/components/AgentChat.vue`（卡片跳转、多轮展示）。

### Phase E：通用优惠券系统（业务完整度）

**内容**：满减券 / 折扣券 / 新人券（现仅有秒杀券），发放方式（后台/注册/满额赠）、核销规则（叠加、适用范围、有效期）。

**技术亮点**：规则引擎 + Redis 预扣 + 与秒杀券统一。

### Phase F：性能压测与调优（硬通货）

**内容**：落地 `项目优化执行方案.md` —— MySQL 加索引 + Sentinel 限流 + JMeter 压测，输出优化前后对比报告。

**技术亮点**：QPS/RT/错误率数据 + 0 超卖验证。

### Phase G（可选，后续评估）

- 操作日志 / 审计（AOP）
- Banner 管理
- 浏览历史（Redis List）
- 通用组件库抽取（两端复用）

```
第 1 步（现在）: Phase A 安全加固 + Phase B 秒杀修复
  ↓ 每个子项修复后：验证 + 记录审查报告到阶段 MD
```

## 业务目标

管理员关键写操作（增删改商品/分类/员工/用户、订单发货与收款、审核/拒绝退款、秒杀活动/券管理、ES 同步等）自动落库 `operation_log`，管理端提供分页查看页，"谁在什么时间对哪个接口做了什么操作"全链路可追溯。

## 技术方案

```
Controller(@OperationLog 标注写操作)
   ↓ Spring AOP @Around("@annotation(...)")
OperationLogAspect：employeeId(BaseContext) → 员工姓名(EmployeeMapper) → 入参 JSON(ObjectMapper) → IP → 组装 OperationLog
   ↓ OperationLogService.save
operation_log 表落库
```

- 切面在方法正常返回或抛出异常后均落库（审计不因失败缺失）
- 参数序列化跳过 `HttpServletRequest/Response/MultipartFile` 等非业务对象，序列化失败降级为参数类名
- 记录字段：`method` 存 HTTP 请求方法 + 请求 URI（如 `PUT /admin/order/deliver`），直观可读
- 登录接口 `/admin/employee/login` 不打注解（当时无登录身份）；查询接口不记录，避免日志爆炸

## 实施步骤（三级：业务 → 步骤 → 代码文件）

### 1. 数据库

**新增文件**：`mysql/operation_log.sql`

```sql
CREATE TABLE IF NOT EXISTS operation_log (
  id bigint AUTO_INCREMENT PRIMARY KEY,
  employee_id bigint COMMENT '操作人ID',
  employee_name varchar(32) COMMENT '操作人姓名',
  module varchar(32) COMMENT '模块',
  operation varchar(64) COMMENT '操作描述',
  method varchar(128) COMMENT 'HTTP方法+URI',
  params TEXT COMMENT '请求参数(JSON)',
  ip varchar(64) COMMENT '操作IP',
  create_time datetime NOT NULL COMMENT '操作时间',
  KEY idx_oper_log_time (create_time),
  KEY idx_oper_log_emp (employee_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin COMMENT='管理端操作日志';
```

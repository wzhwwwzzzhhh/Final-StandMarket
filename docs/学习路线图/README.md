# Final-StandMarket 学习路线图

> **核心理念：每个步骤 = 制造一个问题 → 分析原理 → 动手解决 → 总结成面试故事**
>
> 不是"为改而改"，每个改动都对应一个真实面试考点。你留下的不仅是代码，更是面试时的谈资。

## 学习方式

每个步骤统一格式：

```
① 考点覆盖    → 涉及哪些八股文知识点
② 项目现状     → 当前代码哪里有问题（文件:行号）
③ 模拟问题     → 如何复现/制造这个生产故障
④ 解决方案     → 具体代码改动
⑤ 面试话术     → 面试时怎么组织语言描述
⑥ 扩展思考     → 面试官可能的追问
```

## 推荐执行顺序

1. **Redis 阶段** → 连接最熟，改造成本低，见效快
2. **MySQL 阶段** → 优化 SQL 立竿见影，面试必问
3. **MQ 阶段** → 完善可靠性，理解削峰填谷
4. **JVM 阶段** → 需要压测环境，可先把参数配好
5. **分布式与面试整理** → 收尾总结

## 预估投入

| 类型 | 耗时 | 示例 |
|------|------|------|
| 简单步骤（配置类） | 0.5-1 小时 | 连接池配置、GC 参数 |
| 中等步骤（制造问题+解决） | 1-2 小时 | 缓存穿透、N+1 优化 |
| 复杂步骤（模拟故障+全链路） | 2-4 小时 | 死锁分析、全链路压测 |

## 工具备忘

- **JMeter / Postman** — 压测与接口测试
- **Arthas** — 在线诊断（watch / trace / dashboard / thread -b）
- **JVisualVM / MAT** — 内存分析（Dominator Tree / Leak Suspects）
- **GCViewer** — GC 日志分析
- **MySQL Workbench** — EXPLAIN 分析
- **RabbitMQ 管理界面** — 队列监控

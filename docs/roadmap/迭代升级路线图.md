# StandMarket 迭代升级路线图

> 基于项目现状分析 + 2025-2026 电商行业趋势整理

## 项目现状

**定位**: B2C 时尚电商秒杀系统「末路衣橱」
**成熟度**: 功能型原型 / 早期生产阶段

| ---------------------------------- | ---------- |
| 用户注册登录 (JWT)                       | ✅ 完善       |
| 商品浏览 / 分类筛选 / Redis 缓存             | ✅ 完善       |
| 购物车 CRUD                           | ✅ 完善       |
| 标准订单流程                             | ✅ 完善       |
| 秒杀活动 (Redis+Lua+Redisson+RabbitMQ) | ✅ 完善（技术亮点） |
| 秒杀券 / 秒杀订单                         | ✅ 完善       |
| 特惠活动                               | ✅ 完善       |
| 地址簿                                | ✅ 完善       |
| 管理后台 (ECharts 统计)                  | ✅ 完善       |
| 员工 / 用户管理                          | ✅ 完善       |
| 阿里云 OSS 上传                         | ✅ 完善       |

### 缺失的关键功能

| 模块            | 状态              | 说明                                        |
| ------------- | --------------- | ----------------------------------------- |
| **SKU 管理**    | ⚠️ 有表无 UI       | `product_sku` 表存在，无 Controller 和前端        |

| **拼团/裂变**     | ❌ 无             | 无社交裂变玩法                                   |

## 第一阶段：补齐电商基本功（预计 1-2 周）

> 投入产出比最高，DB 表已存在或改动最小

### 1.1 SKU 管理

- **内容**: 商品规格（颜色、尺码）的 CRUD
- **后端**: 新增 `SkuController`，对接已有 `product_sku` 表
- **前端**: 管理端商品编辑页增加 SKU 管理面板
- **价值**: 让商品真正支持多规格选择

### 1.2 组合套餐管理

- **内容**: 商品捆绑销售的 CRUD
- **后端**: 新增 `CombinationController`，对接已有 `combination` / `combination_product` 表
- **前端**: 管理端增加套餐管理页面
- **价值**: 利用已有表结构，快速增加捆绑销售能力

### 1.3 支付网关接入

- **内容**: 对接真实支付网关
- **方案**: 支付宝沙箱环境 或 Stripe 测试环境
- **改动**: 替换手动确认付款流程，增加支付回调处理
- **价值**: 秒杀链路真正闭环，项目完整度大幅提升

### 1.4 物流/发货

- **内容**: 增加快递跟踪
- **改动**: `orders` 表增加 `tracking_company`、`tracking_number` 字段，管理端发货时填写
- **价值**: 订单状态机完整（待支付→待发货→已发货→已完成）

### 1.5 商品评价

- **内容**: 订单完成后可评价
- **改动**: 新增 `review` 表 + CRUD，商品详情页展示评分
- **价值**: 用户决策的重要参考，电商平台标配

### 1.6 收藏夹

- **内容**: 商品收藏/取消收藏
- **改动**: 新增 `favorite` 表（user_id, product_id, create_time）
- **价值**: 轻量高感知的功能

## 第二阶段：提升商业完整度（预计 1-2 个月）

### 2.1 通用优惠券系统

- **区别于秒杀券**: 满减券、折扣券、新人券、店铺券
- **发放方式**: 后台发放、注册自动发放、满额赠券
- **核销规则**: 叠加规则、适用商品范围、有效期管理
- **参考**: 拼多多"百亿补贴"的品牌化上行策略

### 2.2 售后服务 / 退款流程

- **售后单**: 新增 `refund` 表，用户发起→管理员审核→退款
- **状态机**: 待审核 → 同意退款 / 拒绝 → 已退款
- **库存释放**: 退款成功后恢复商品库存

### 2.3 Banner / 广告位管理

- **内容**: 首页轮播图后台可配置
- **改动**: 新增 `banner` 表（image, link, sort, status）
- **价值**: 运营人员可独立管理首页视觉

### 2.4 操作日志 / 审计日志

- **内容**: 员工关键操作可追溯
- **方案**: AOP 切面记录操作日志入库
- **价值**: 生产环境必备的安全审计能力

### 2.5 商品搜索增强

- **内容**: 支持分词搜索
- **方案**: 接入 Elasticsearch，商品数据同步到 ES
- **价值**: 搜索体验质的提升

### 2.6 浏览历史

- **内容**: 记录用户最近浏览的商品
- **方案**: Redis List 存储最近 50 条
- **价值**: 低成本的个性化体验

## 第三阶段：差异化亮点（预计 2-3 个月）

> 让项目在展示/简历中脱颖而出

### 3.1 AI 智能客服（最高优先级差异化）

**现状**: agent-service 模块（FastAPI + LangGraph + Redis 记忆 + Elasticsearch）是空壳

**实现内容**:
| 能力 | 技术方案 | 价值 |
|------|---------|------|
| 商品知识库问答 | LangGraph + ES 商品搜索 | 用户问"红色连衣裙"直接推荐 |
| 订单状态查询 | 对接后端 API | "我的订单到哪了？" |
| 尺码推荐 | 身高体重 → 尺码规则引擎 | 减少退换货 |
| 搭配推荐 | 关联购买 + AI 生成 | 提升客单价 |

**行业参考**: 伯俊科技 AI agent 将连带销售率从 1.2 件/单提升至 2.8 件/单

### 3.2 直播带货（当前最热方向）

**行业趋势**:

- Whatnot 2025 年直播 GMV 达 $80 亿，用户日均使用 95 分钟
- 中国直播电商年 GMV 超 $7000 亿
- 服装品类天然适合直播（面料展示、上身效果、动态搭配）

**实现方案**:
| 组件 | 技术 | 功能 |
|------|------|------|
| 直播间管理 | 管理端 CRUD | 创建直播活动、关联商品 |
| 直播推流 | OBS + RTMP / 腾讯云 LVB | 主播推流 |
| 直播观看 | FLV.js / HLS.js | 用户端拉流 |
| 实时聊天 | WebSocket ✅ 已引入 | 弹幕、互动 |
| 直播间下单 | 购物组件浮层 | 边看边买 |
| 秒杀穿插 | 对接现有秒杀模块 | 直播间限时秒杀 |

### 3.3 AI 穿搭推荐

- 基于商品标签 + 用户行为的搭配推荐
- 对话式选衣（通过 agent-service 实现）
- 场景化推荐（通勤、约会、运动）

### 3.4 拼团 / 社交裂变

- **参考**: 淘宝秒杀频道拼团玩法、拼多多"砍一刀"
- **方案**: 新增 `group_buy` 表，用户开团→分享→成团→优惠
- **价值**: 低成本获客，结合秒杀场景效果更佳

### 3.5 AR 虚拟试衣 / 尺码推荐

- **参考**: Zalando AR 鞋子试穿（规划覆盖 70,000 SKU），退货率降低 10%
- **方案**: 接入 AR.js 或第三方 SDK，先从尺码推荐做起

## 第四阶段：技术架构升级（长期）

### 4.1 Java 17 + Spring Boot 3

| 升级内容            | 收益                                 |
| --------------- | ---------------------------------- |
| Java 17         | 虚拟线程（无痛高并发）、Records、密封类、Switch 表达式 |
| Spring Boot 3   | GraalVM 原生编译、Jakarta EE 迁移、AOT 编译  |
| Spring Security | 替代当前 JWT 拦截器方式                     |

### 4.2 MyBatis-Plus

- 替代原生 MyBatis，减少 60%+ CRUD 样板代码
- 内置分页、条件构造器、代码生成器

### 4.3 分布式事务（Seata）

- **场景**: 秒杀下单涉及 Redis 扣减 + 订单写入 + 库存更新
- **现状**: 最终一致性，无强事务保证
- **参考**: 阿里云《电商库存系统超卖事故复盘》— 接口必幂等、事务必闭环

### 4.4 日志与监控

| 工具                   | 用途                 |
| -------------------- | ------------------ |
| ELK / Loki           | 日志收集 + 可视化查询       |
| Prometheus + Grafana | 系统指标监控（QPS、延迟、错误率） |
| Sentry               | 错误追踪               |

### 4.5 K8s 容器编排

- docker/ 目录已有 Docker Compose 基础
- 补充 K8s Deployment / Service / HPA 配置
- 水平扩缩容能力

### 4.6 分库分表（ShardingSphere）

- 订单表按用户 ID 分片
- 应对千万级订单量场景
- **前置条件**: 索引优化 → 读写分离 → 分库分表

## 行业趋势参考

### SHEIN 迭代路径（2008→2024）

```
婚纱独立站 → 快时尚自营品牌 → 全品类平台（自营+第三方） → 本地化全球布局
  2008          2012-2014              2023                       2024-
```

- **核心**: 小单快反（100件起订、7天交付）、数据驱动设计、售罄率 98%
- **关键转折**: 2023 年从自营品牌转向开放平台（SHEIN Marketplace）

### 拼多多 / Temu 迭代路径（2015→2024）

```
社交拼团（国内）→ 百亿补贴品牌上行 → 多多买菜 → Temu 全托管出海
  2015             2019              2020            2022-
```

- **核心**: C2M 去中间化、游戏化购物、社交裂变
- **出海打法**: 全托管模式、极致低价、超级碗广告

### 2025-2026 时尚电商关键词

| 趋势              | 说明             | 代表                            |
| --------------- | -------------- | ----------------------------- |
| **AI Agent 购物** | 从搜索到成交的全流程智能代理 | Amazon Rufus, Hey Savi        |
| **直播即基础设施**     | 产品页面正在变成「人」    | Whatnot（$8B GMV）, TikTok Shop |
| **社交/内容驱动**     | 从交易变成持续关系      | Zalando 社交时尚生态, Poshmark 改版   |
| **全渠道融合**       | 线上线下边界模糊       | 淘宝闪购（远中近三场物流）                 |
| **灵活支付**        | BNPL 渗透率持续提升   | Klarna, Affirm                |
